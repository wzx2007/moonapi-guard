# 三分钟演示脚本

1. 启动：`node scripts/serve.mjs`，打开 <http://127.0.0.1:4173>。
2. 开场：“这是一个用 MoonBit 实现的接口兼容性检查器。它比较 OpenAPI 描述，并区分请求和响应方向。”
3. 默认示例点击“检查兼容性”：展示 7 项风险。说明 `/health` 被删除、limit 上限收紧、status 请求参数变必填，以及响应字段类型和枚举变化。
4. 讲解一个细节：“同样是新增枚举值，请求通常更宽容，响应却可能让旧客户端收到不认识的状态。我们的核心库按方向判断。”
5. 切换“兼容性变更”，载入并检查，显示支持范围内兼容。
6. 切换“鉴权要求收紧”，检查新增凭据要求；再切换“需要人工复核”，展示尚未支持的响应头契约。
7. 导出 HTML，打开独立报告；展示 CLI：`node bin/moonapi-guard.mjs examples/old.json examples/breaking.json --format json`。进程退出 1，可用于 CI 阻止发布。
8. 说明限制：“第一版支持 OpenAPI 3.0 JSON 的明确子集，不证明服务端运行时行为。复杂结构会列为复核项。完整规则和测试命令在仓库中。现在还可以搜索风险项、取消后台分析及通过 CLI 导出 SARIF。”

## 常见问题

**MoonBit 用在哪里？** 解析流程、引用解析、输入检查、双向 Schema 兼容性、报告模型和全部风险规则。JavaScript 只做宿主 I/O 与展示。

**为什么不用现成工具？** 成熟工具验证了需求；本项目提供可被 MoonBit 程序直接复用的纯函数核心，并演示跨后端测试和同一引擎的多端使用。没有声称首次发明 API diff。

**为什么有些变化只提示复核？** 没有实现或无法单靠描述判定的语义，不能假装已经检查；默认 CI 策略会阻止这些结果。

**能保证没有兼容问题吗？** 不能。输入契约、支持子集与实际运行行为是不同层次；文档记录了保守误报和未支持语义。
